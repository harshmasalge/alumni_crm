# M1 — Secure People Registry and 360° Profiles

## Outcome

Staff can search, open, and maintain a persistent alumni/donor record while retaining the alumni's post-IITGN education and career history. This is the first operational CRM release.

## Required user behaviours

### Full profile from person lookup

- An exact Roll Number search returns the matching alumnus.
- A name search supports partial matching and returns matching alumni.
- Selecting either search result opens the same complete 360° profile: identity/contact, IITGN academic summary, post-IITGN education, current and prior affiliations, donations summary, activity/audit timeline, and profile-freshness information.
- Access to sensitive tabs and fields remains governed by server-side permissions.

### Education and career history

- Post-IITGN qualifications are separate dated records; adding a qualification does not overwrite earlier education.
- An affiliation contains organisation, designation, sector, location, start date, end date, and current/past status.
- Adding a new current job closes the previous current affiliation and preserves it as past history.
- A profile presents the complete timeline in a readable order.

### Profile freshness

- Store a `last_substantive_profile_update_at` timestamp for each profile.
- Define a substantive update as an approved create/edit to profile data, education, affiliation, contact, or other specified profile domain data. Reads, exports, login, audit creation, and scheduled jobs do not count.
- Calculate `days_since_profile_update` from that timestamp; do not persist an incrementing daily counter.
- The CRM home screen shows the count of alumni with `days_since_profile_update > 365`.
- Selecting the count opens the People list with the equivalent server-side filter already applied.

### Organisation search

- Searching `Google` matches organisation names across all affiliations, not merely the current employer.
- The result lists each alumnus once and displays the relevant association status: `Current`, `Past`, or both when applicable.
- The profile reveals all matching affiliations and their dates.

## Data-model notes

```text
constituent
  ├── alumni_profile
  ├── education_record (0..n, dated)
  └── affiliation (0..n, date range, is_current)
```

Use `constituent_id` UUID for relationships. Index normalised Roll Number, display/search name, and normalised organisation name. Design the affiliation query for a person appearing once in organisation search results even with multiple historical records.
